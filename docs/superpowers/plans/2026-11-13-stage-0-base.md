# Stage 0, the base: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build stage 0 of the full-cycle design: the safety fixes, origin labels on every bot
issue, the owner's desk and page, more review tasks, and the record of decisions.

**Architecture:** Everything new is a script without a model. Three shared pieces carry it:
`secret_filter.py` (one check, used by the three scripts that publish model text),
`bot_issues.py` (the one place that finds, opens, labels and pauses bot issues) and the desk
(`desk_gather.py` reads facts, `desk.py` turns them into `desk.json`, `desk_post.py` shows that
file as the "Kitden desk" issue). The work lands as six pull requests, one per part, and two
more when their dates come (part 7).

**Tech Stack:** Python 3.13, standard library only in scripts (workflows run them with
`--no-project`); pytest and ruff; GitHub Actions; the `gh` CLI; StepSecurity Harden-Runner
v2.22.4.

**Spec:** [docs/superpowers/specs/2026-11-13-full-cycle-design.md](../specs/2026-11-13-full-cycle-design.md).
Read it first. "Spec 1.6" below means its part 1.6.

## Global Constraints

- Work in a worktree on a branch of your own, one per part:
  `git worktree add .claude/worktrees/<name> -b <branch> origin/main`. Never the main checkout,
  never another session's branch, never a bare `git stash`.
- Before each commit in kitden-sdlc run `uv run pytest -q`, `uv run ruff check .` and
  `uv run python scripts/check_agent_workflows.py .github/workflows`. All three must pass.
- A task that edits a workflow also runs the `agentic-actions-auditor` skill on that file and
  `uvx --no-config zizmor==1.32.0 --no-config --no-ignores .github/workflows`, as CI does.
- Every action is pinned by its full SHA, with the tag in a comment.
- RULES.md and the README change in the same commit as the workflow or script they describe.
- New scripts import the standard library and each other only. No new dependency.
- Docs are short, plain English, and say each thing once. Commit subjects are short and plain,
  with no `feat:` prefix. Each commit message ends with
  `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.
- No step in this plan runs a model. Running the evals waits for the owner's yes.
- Names from spec 1.6 are fixed: labels `automated`, `client-change`, `release`, `desk`,
  `confirmed`, `false-alarm`; switches `AGENTS_ENABLED`, `WATCH_LIVE`, `REVIEW_LIVE`; the issue
  title `Kitden desk`; the pages `docs/owner.md` and `docs/decisions.md`.
- The bot that opens issues is `kitden-lantern[bot]`. The maintainer is `KonstantinStarovoytov`.
- Only the owner sets a repository variable, a secret or a pin. A step marked **Owner** stops
  and asks.
- The parts are done in order. Part 6 touches nothing the others touch and can go any time
  after part 2.

## Review Focus

What the spec implies but says little about. Each line has its test in the task named.

1. A person opens an issue with a bot's title ("Time for a release?", "Kitden desk",
   "The client watcher is paused"), even with the label `automated`: no bot edits or closes it,
   and the bot opens its own. Task 8.
2. A pull request commits a link to a file outside the repository, or the quoted string is only
   a file's name: the filter reads git objects, follows no link, and knows file names. Task 5.
3. A title on the desk is a stranger's text: `@name`, `#1`, a Markdown link, `<!--`, `|` or a
   new line must not ping, link or break the page. Task 15.
4. A day without data (GitHub cannot be read, the watcher never ran): the light is grey, never
   green, and the desk is still written. Tasks 13 and 14.
5. Fewer than 10 verdicts, both verdict labels on one issue, or a verdict on the weekly
   summary: no pause, and that issue is not counted. Task 10.

```python
@dataclass
class Facts:
    """What was read. None means the read failed or was never made."""
    issues: list[dict] | None = None      # every Kitden issue, open and closed, no pull requests
    pulls: list[dict] | None = None       # pull requests updated in the last 90 days
    reviews: list[Review] | None = None
    checks: list[dict] | None = None      # check runs of main's newest commit
    required: list[str] | None = None     # the checks main requires
    runs: dict[str, int | None] = field(default_factory=dict)  # agent id -> runs, last 7 days
    watch_log: list[dict] | None = None   # the watcher's log.jsonl
    stars: int | None = None
    downloads: int | None = None          # PyPI, last month

def light_works(checks) -> dict                      # {"id", "name", "state", "why"}
def light_clients(issues, watch_log, now) -> dict
def light_bugs(issues, now) -> dict
def light_agents(issues, required, now) -> dict
def light_queue(waiting) -> dict
def overall(states: list[str]) -> str
def waiting(issues, pulls, reviews, now) -> list[dict] | None
def use(issues, pulls, stars, downloads, now) -> dict
def week(roster, reviews, issues, pulls, runs, now) -> list[dict]
def found_by(reviews, issues, now) -> list[dict]     # this month and the two before, newest first
def misses(issues, reviews, now) -> list[dict]
def build(facts: Facts, roster: dict, now: datetime) -> dict
```

The rules. Amber is always past half of the red limit.

| Light | Grey | Red | Amber |
|---|---|---|---|
| Works | no check run, or `None` | a conclusion of `failure`, `timed_out`, `cancelled`, `action_required` or `startup_failure`; `why` names the checks | a check not `completed` |
| Clients | `issues` is `None`, or the watcher's newest log line is over 2 days old or missing | an open bot issue with `client-change`, `confirmed` and `major` opened over 7 days ago | over 3.5 days |
| Bugs | `issues` is `None` | an open bot issue with `confirmed` and `major` opened over 14 days ago; or open `bug` issues grew on each of the last three Mondays | over 7 days; or grew on the last two |
| Agents | `issues` or `required` is `None` | a required check whose name starts with `review /`; or more than 2 bot issues with `client-change` and no `summary`, opened in this ISO week | an open bot issue with `desk` whose title ends with " is paused" |
| Queue | `waiting` is `None` | an item waited over 7 days | over 3.5 days |

`overall`: the first of `red`, `amber`, `grey`, `green` that any light has. Open `bug` issues
on a Monday: created before that Monday 00:00 UTC and not closed before it. A bot issue is one
whose author is `BOT`; a bot's pull request is one whose author's login ends with `[bot]`.
Days have one decimal.

The waiting list (`None` when `issues` or `pulls` is `None`), oldest first inside each kind:

| Kind | What | `do` |
|---|---|---|
| `pull` | an open pull request by a bot whose branch starts with `agent/` or `prepare-v` | "Review it and merge, or close it." |
| `verdict` | an open bot issue with `client-change`, without `summary` and without a verdict | "Put `confirmed` on it, or close it with `false-alarm`." |
| `release` | an open bot issue with `release` | "Do what it says under What to do." |
| `paused` | an open bot issue with `desk` whose title ends with " is paused" | "Close it to start the agent again." |
| `spot-check` | see below | "Look at the change, then 👍 or 👎 on its Agent review comment." |

The spot check (spec 2.4): take the reviews that are `clean` and whose pull request merged in
the 7 days before this week's Monday 00:00 UTC. If the owner voted on any of them, there is no
spot check. Otherwise it is the one merged last; its `days` count from that Monday, its
address is that pull request in `count_reviews.REPO`, and its title is "#N, reviewed with no
findings".

`use`: issues and pull requests opened this month by anyone who is neither the maintainer nor
a bot, then the two numbers as given.

`budget`: `agents` is `{"agent", "runs", "cap"}` for each roster agent, `keys` is the roster's
list as it is. Model calls are not recorded anywhere yet, so stage 0 shows runs only (call).

`week`: one row per roster agent. `runs` from `facts.runs`. For `claude` and `luna`: `did` is
the pull requests it answered on whose comment changed in the last 7 days, `agreed` and
`disagreed` the owner's 👍 and 👎 on those comments. For `watcher`: `did` is the bot's
`client-change` issues opened in the last 7 days, `agreed` and `disagreed` its `confirmed` and
`false-alarm` issues opened in the last 30. For `release-prep`: `did` is the pull requests
from `prepare-v` branches opened in the last 7 days; the other two are `None`.

`found_by`, by the month something was opened or merged: `review` is `fixed` findings;
`watcher` is the bot's `client-change` issues with `confirmed`; `owner` is `bug` issues by the
maintainer; `others` is `bug` issues by anyone else who is not a bot; `nightly` and `tester`
are `None` until their stages.

`misses`: a `bug` issue opened in the last 30 days whose body has the form's `### Caused by`
heading followed by `#N` or a pull request address, where pull request N has a review.
